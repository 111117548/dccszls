# 系统架构

## 设计目标

平台服务于电除尘器建设期的现场质量管理，强调手机端低门槛操作、工程数据可追溯和弱网络环境下的渐进可用性。数字孪生承担施工范围、部件状态和质量信息的空间入口，不承担结构计算或设备运行诊断。

## 客户端

- 首页：项目/设备上下文、进度总览、13类部件和施工数字孪生。
- 工作台：到货、安装检查、检验记录、缺陷、报告和系统功能入口。
- 今日：需要跟进的整改、复验和预警事项。
- 我的：账号、协作授权、接口与项目管理。

`components/construction-twin-3d`使用微信原生`Canvas type="webgl"`和程序生成几何体，不依赖浏览器Three.js或外部模型CDN。重复构件使用实例化绘制，场景支持施工回放、部件点击、旋转、缩放、进度筛选和移动端画质分级。

## 领域数据

`utils/v4-foundation.js`等模块维护项目、设备、13类部件、质量节点及旧版本数据迁移。业务记录通过稳定ID关联，避免显示顺序变化破坏历史检查、缺陷或报表关系。

## 云端能力

| 云函数 | 责任 |
| --- | --- |
| `ai-analyze` | 图片与检查条目的AI辅助分析 |

云端部署、集合权限和环境变量见[云开发部署](../CLOUD-DEPLOYMENT.md)；飞书应用配置见[飞书集成](../FEISHU-INTEGRATION.md)。

## 安全原则

1. 客户端不保存AI或飞书密钥。
2. 敏感凭据只通过云函数环境变量提供。
3. 开放协作使用工单令牌限制访问范围。
4. AI结果必须人工确认后才能进入正式质量记录。
5. 生产数据库遵循最小权限，并区分演示与生产环境。
6. 报告和图片的访问权限应与项目成员及协作令牌绑定。

## 性能策略

- 模型主体采用基础几何复用和实例化批渲染。
- 按设备基准能力选择渲染倍率，并在真机启用抗锯齿。
- 未到序部件不进入可见批次，减少无效绘制。
- 施工机械采用确定性循环动画，不引入完整物理引擎。
- 背景厂区使用低细节体块，主体部件保留更高信息密度。
