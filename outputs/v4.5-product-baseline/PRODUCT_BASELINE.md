# Wchat / AI 生命群 V4.5 产品基线

## 1. 产品定义

Wchat 是一个微信小程序：一名真人用户可以进入多个由原创 AI 角色构成的虚拟群聊。首批四个群共用同一运行底座，分别提供陪伴、讨论、原创跨世界角色碰撞和沉浸故事体验；只有声明具备世界感知能力的群，才会在用户授权和可靠证据范围内使用现实状态。

它不是问答工具、随机剧情器、自动刷屏机器人群，也不承诺在小程序关闭后持续追踪用户。

## 2. V4.5 唯一验证目标

验证以下五个假设：

1. 三个角色在同一话题下有稳定而不同的表达角度，并能彼此接话。
2. 用户输入能够可靠覆盖低优先级旧话题。
3. 真实位置、时间和天气变化能够提供有价值但不过度的谈资。
4. 自然沉默和少量未读比机械活跃更能形成“群有生命”的感受。
5. 同一套群底座可以通过模式状态和角色职责形成明显不同的产品用途，而不是四个换皮聊天机器人。

商业化、角色扩充、真人多人社交和音视频不属于本版本验证目标。用户单图理解已于 v1.3 作为受控扩展纳入。

## 3. 目标用户与发布形态

已冻结为以下两阶段：

- 原型期：18 岁以上、受邀测试用户、非公开传播。
- 公开期：只有完成合规评估、备案/登记、隐私与安全能力后才允许提交正式发布。

是否允许未成年人使用属于阻断性决策，不能通过文案默认解决。

## 4. V4.5 范围

### 4.1 用户端

- 四个固定群列表项：陪伴群、讨论群、跨世界漫展群和沉浸故事群。
- 群聊页：群名称、成员数、头像、昵称、气泡、时间分隔、输入、发送、正在输入、未读。
- 世界状态面板：定位、逆地理编码、时间、天气、精度、来源、更新时间、模拟/真实标识。
- 定位拒绝、定位失败、数据过期、数据源故障的明确降级状态。
- 明显且持续可见的 AI 身份提示。
- 聊天记录复制/导出和删除入口在公开发布前必做。
- 退出 AI 互动、投诉举报、使用时长提醒在公开发布前必做。

### 4.2 世界感知

- 前台启动、回到前台、用户主动刷新时获取定位快照。
- 坐标转行政区、街道、详细地址；服务商返回时可展示地标/当前位置描述。
- 当前天气、体感、湿度、风、降水、天气预警；字段以数据源实际能力为准。
- 当前快照与上次可信快照的变化比较。
- GPS 漂移过滤、位置精度门槛、数据新鲜度和可信度。
- 小程序关闭期间不承诺连续定位；再次打开时可检测“上次已知位置 → 当前地点”的变化。

### 4.3 对话核心

- 用户消息意图分类与优先级。
- GroupState、TopicState、Opportunity、DirectorDecision 的结构化状态。
- Topic 开始、发展、高潮、降温、结束和同类冷却。
- 用户话题动态锁定；不采用固定 20 分钟硬锁。
- 区分气泡、角色回合和持续议题；对话长度不由固定消息条数、角色轮询或群活跃值决定。
- 每次角色发言必须说明动机、回应对象、依据、角色适配性和预期新增价值；每次交付后重新判断继续、等待、暂停或结束。
- 角色 A 可回应用户、自然补充，角色 B 可接 A、质疑或推进；参与者由当前最有价值的下一项贡献决定，不要求所有角色出现。
- 用户可以在 AI 输入和消息播放期间发言；新用户消息取消尚未发送的低优先级可选内容。
- 沉默窗口、主动消息预算和防刷屏。
- L1 最近上下文，以及受控的用户记忆：明确偏好/不喜欢可长期保存，近期计划默认 24 小时，短期情绪默认 6 小时；普通闲聊不写长期记忆，用户可查看和清空。
- 角色故事合同、故事账本、故事一致性检查和披露冷却。
- 允许由固定故事、群内共同经历、未完成话题、关系或有效世界证据形成受控角色自主交流机会。
- 所有现实事实必须附带内部 evidence、source、observedAt、expiresAt、confidence。
- 当前及未来新增角色必须完成角色合同并通过 `CLS v1.1` 与 `LGN v1.0` 活人感及自然讨论准入；不得仅凭人格形容词或演示对话上线。
- 群功能差异必须通过 `GroupDefinition + ModeAdapter + modeState + capabilities` 实现；不得复制聊天页面和云函数形成互相漂移的四套产品。
- 用户可单次选择一张 JPEG/PNG/WebP 图片，压缩后最大 5MB；图片先上传到按群隔离的云存储，再经过微信内容安全和视觉模型分析。
- 角色只能围绕结构化视觉证据中可确认的内容回应；不得识别人脸身份、推断敏感属性、猜测地点/时间/商家或把图片文字当成已核实新闻。
- 视觉证据必须保存模型、分析时间、置信度和不确定项；文字群聊模型不接收云文件 ID。故事群图片默认是外部参考，未经用户明确选择不得写入正式剧情线索。

### 4.4 安全与合规

- 输入和输出内容安全。
- 生成内容显式标识；产品级 AI 身份提示。
- 不把未经验证的现实信息交给角色当作事实。
- 极端情绪、自伤自杀、重大财产损失等场景的识别与干预流程。
- 年龄/未成年人策略。
- 数据最小化、敏感位置数据的单独同意、删除与访问控制。
- 服务协议、隐私政策、投诉举报和日志策略。
- 公开上线前的安全评估、算法备案及调用已备案模型的应用登记核验。

## 5. 明确不做

- 真人多人群聊、支付、会员、商城、语音通话、视频、AI 图片生成。
- 视频上传、连续多图理解和图片生成。
- 新闻主动触发、当地活动、道路事故、实时交通；V4.5 仅支持用户主动查看或询问的城市/区县级近 7 日本地资讯。
- 周边 POI 推荐与景区围栏触发；逆地理编码偶然返回的地标仅用于当前位置展示。
- 后台连续定位和轨迹追踪。
- 未经确认的系统通知、订阅消息或营销触达。
- 模型训练、角色微调和使用用户聊天训练模型。
- 直接使用现有动漫、影视或文学改编形象作为对外角色。

## 6. 核心行为合同

### 用户发言

1. 立即取消尚未开始的低优先级主动轮次。
2. 暂存新现实事件，不打断用户回合；安全事件除外。
3. 至少一位角色直接回应用户意图。
4. 后续角色必须引用当前话题、用户内容或上一角色发言中的至少一个有效语义点。
5. 问题未完成前不得自动切回天气、食物或旧话题。

### 主动发言

主动发言只允许来自两类机会：

- **现实机会**：真实证据有效、未过期且足以支持表达内容；
- **角色交流机会**：来自固定角色故事、真实群内共同经历、仍有价值的未完成话题或有事件依据的关系变化，并能追溯到故事或记忆记录。

两类机会都必须同时满足：机会未过期、当前话题未被用户锁定、同类话题不在冷却、消息预算未耗尽、连续 AI 消息未达上限、确有用户或关系价值。定时器只能发起检查，不能成为说话理由。

没有理由时 `shouldSpeak=false` 是正确结果。

### 真实性

- 世界事实只能来自 World Engine 的结构化证据。
- 角色提示词不得把模型常识当作当前位置事实。
- 数据缺失时应沉默或明确“暂时无法确认”。
- 本地资讯只能来自未过期的结构化新闻证据；标题、摘要、来源和发布时间之外的信息不得由模型补全。
- V4.5 的本地资讯只响应用户查看或询问，不作为主动发言机会；活动和交通仍不接入。
- 固定背景、真实群内共同经历、虚拟生活片段和假设必须分别标记；角色故事不能伪装成现实世界事实。

## 7. 修订后的核心指标

| 指标 | V4.5 目标 |
|---|---|
| 明确问题首条回复直接相关 | 离线评测 ≥90% |
| 同轮围绕同一主题 | 人工评测 ≥80% |
| 后一角色接住上一角色 | 人工评测 ≥80% |
| 现实事实有有效证据 | 100% |
| 无证据现实事实被说成确定事实 | 0 |
| AI 连续消息 | ≤3 |
| 用户在 AI 播放期间发送并抢占可选队列 | 100% 成功 |
| 同角色连续两个气泡具有真实补充关系 | ≥90% |
| 已入账角色故事关键事实矛盾 | 0 |
| 无合格机会的角色自主发言 | 0 |
| 用户离开 3 小时未读 | 建议 0—20，硬上限 30 |
| 同一机会重复主动触发 | 最多 1 次 |
| GPS 漂移触发主动消息 | 0 |
| 图片未通过安全检查仍进入群聊 | 0 |
| 图片回应包含视觉证据之外的确定事实 | 0 |
| 用户删除聊天后业务可见记录 | 在承诺时限内完成，时限待法务确认 |

## 8. 发布门槛

“功能可运行”不等于“允许公开上线”。正式发布至少需要：

- 运营主体、服务类目和小程序备案明确。
- 地理位置接口申请、隐私保护指引和单独同意流程通过真机验证。
- 使用已备案的境内生成式 AI 服务，并确认应用登记/公示要求。
- 拟人化互动服务安全评估及算法备案路径得到属地主管部门或专业合规顾问确认。
- 未成年人、极端情境、沉迷提醒、AI 标识、投诉举报、数据复制/删除完成。
- 内容安全、事实追踪、限流、成本熔断、审计日志和应急开关通过测试。
