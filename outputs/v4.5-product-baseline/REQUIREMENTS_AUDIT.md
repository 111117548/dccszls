# V4.5 开发前需求审计

> 2026-07-24 受控变更：依据 ADR-019，城市/区县级近 7 日本地资讯的“查看与用户查询”能力已进入 V4.5；新闻主动触发、活动、交通与 POI 仍按本审计结论推迟。

## 1. 总体判断

原需求的核心体验定义清晰，尤其是用户优先、话题生命周期、Director 与生成解耦、真实机会而非随机事件、沉默优先，这些都适合落为确定性领域规则。

返工风险主要不在聊天 UI，而在以下六处：发布合规被低估、后台感知能力假设不成立、V4.5/V5 数据范围交叉、未读数量指标与沉默原则冲突、角色知识产权风险、模型调用次数与事实可靠性没有预算模型。

## 2. 必须现在决定

### M01 公开发布还是封闭原型

- 缺失：没有说明 V4.5 是内部原型、体验版测试还是面向公众发布。
- 影响：决定是否必须在本阶段完成安全评估、算法备案/登记、投诉举报、未成年人、数据权利等能力。
- 推荐：V4.5a 先做 18+ 邀请制原型；V4.5b 才做公开发布合规门槛。
- 状态：已确认，采用推荐方案。

### M02 运营主体与合规资源

- 缺失：个人还是企业主体、注册地、属地网信部门、是否有法务/合规预算。
- 风险：产品高度匹配 2026-07-15 生效的拟人化互动服务定义；公开上线需安全评估，且要求算法备案和年度核验。分发平台也将核验评估、备案情况。
- 推荐：以中国大陆企业主体筹备；开发前做一次专业合规咨询。本文不是法律意见。
- 状态：已确认，采用推荐方案。

### M03 年龄与未成年人策略

- 冲突：原需求无年龄体系，新规要求年龄相关信息、未成年人识别与模式；不满 14 周岁还涉及监护人同意。
- 推荐：首个公开版本仅向 18 岁以上用户提供；若要接纳未成年人，另立合规与产品专项，不能作为普通增量功能。
- 状态：已确认，采用推荐方案。

### M04 角色知识产权

- 风险：路飞、五条悟是受保护角色；林黛玉原著虽进入公有领域，但具体影视/游戏造型、配音和改编表达仍可能受保护。使用姓名、头像、经典台词或高度近似设定会带来权利和审核风险。
- 推荐：三个完全原创角色，仅抽象保留“热情行动派 / 轻松锐评者 / 细腻观察者”的人格维度。
- 状态：已确认，采用推荐方案。

### M05 技术与部署路线

- 缺失：原生/Taro/uni-app、云开发/独立后端、数据存储地区、定时任务和日志体系未定。
- 推荐：微信原生 TypeScript + 服务端 TypeScript；首期使用中国大陆合规云资源。领域层与云厂商适配层分离，避免锁死。具体选 CloudBase 还是独立托管由团队经验和备案主体决定。
- 状态：已确认，采用推荐方案。

### M06 模型服务商

- 风险：模型价格、延迟、上下文、工具调用、内容安全、数据留存和备案状态会改变架构。
- 推荐：只选已备案、支持中国大陆公开服务、提供结构化输出和服务端调用的模型；应用侧确认登记和公示要求。密钥只放服务端。
- 状态：已确认，采用推荐方案。

### M07 离线期间“群在生活”的实现语义

- 平台限制：小程序关闭后不能依赖客户端定时器持续运行，普通定位接口也不能等同于全天后台追踪。后台持续定位权限具有场景和审核限制，不应作为首版前提。
- 选项：服务端定时生成、事件驱动生成、再次打开时回放式重建。
- 推荐：混合策略——高价值服务端事件可以生成最多 1—2 条；其他变化在用户重开时根据前后快照生成“刚刚注意到”的少量消息。
- 状态：已确认，采用推荐方案。

### M08 精准位置的保存范围

- 风险：连续精准定位轨迹属于敏感个人信息；详细地址还可能暴露住所、医院等高敏场所。
- 推荐：V4.5 不存轨迹。原始坐标只用于即时处理并短期加密保存；长期只保存城市/区县和语义事件，不把精确位置送入长期记忆。
- 状态：已确认，精确坐标加密保留不超过 24 小时，之后删除或粗化。

### M09 未读指标修订

- 冲突：“70% 沉默”“无真实变化不说话”与“离开 3 小时理想 5—20 条”会迫使系统制造消息。
- 推荐：改为 0—20 条，硬上限 30；考核“每条有有效触发理由”，不设置最低条数。
- 状态：已确认，采用 0—20 条、硬上限 30。

### M10 商业地区与预算边界

- 缺失：首发地区、预计 DAU、每用户消息量、AI 月预算、地图/天气预算、可接受延迟。
- 推荐：首发中国大陆；在模型选型前提供 100 / 1,000 / 10,000 DAU 三档预算。
- 状态：已确认，中国大陆首发，原型 ≤100 名受邀用户。

## 3. 可以采用推荐默认值

### D01 UI 技术

采用微信原生小程序 + TypeScript，优先保证原生能力、审核一致性和包体可控；暂不为跨端付出抽象成本。

### D02 V4.5 POI 边界

逆地理编码可以展示服务商返回的当前位置描述或地标；周边检索、排序、营业状态和景区围栏推迟到 V5。世界面板对未接入字段显示“未接入”，不放模拟事实冒充真实信息。

### D03 天气源

候选默认使用和风天气等有明确开发文档、预警能力、授权与计费说明的服务。最终选择须在开发前核验商业授权、归因展示、配额和数据留存条款。

### D04 地图源

中国大陆默认优先腾讯位置服务，减少坐标系和微信生态集成成本。逆地理编码和 POI 密钥经服务端代理；不能在小程序包内放可滥用的服务端密钥。

### D05 位置采样

只在启动、回前台、用户刷新和明确需要位置的交互中采样；短时间缓存。高精度失败时退化为低精度并展示精度，不重复弹授权。

### D06 世界事实模式

所有事实使用统一 `EvidenceEnvelope`：`provider`、`sourceId`、`observedAt`、`fetchedAt`、`expiresAt`、`confidence`、`isSimulated`、`rawHash`。过期事实不得进入生成上下文。

### D07 规则与模型边界

优先级、锁定、冷却、发言上限、消息预算、事实许可、记忆保留由代码决定；模型只做意图候选和自然语言生成，Director 首版以确定性规则为主。

### D08 一轮模型调用

默认一次规划/意图调用（可被规则跳过）+ 一次批量生成 1—3 条连续角色消息；不为每个角色单独调用模型。输出必须符合 JSON Schema，失败最多重试一次。

### D09 短期记忆

L1 最近 20 条消息；L2 仅保存带类别、来源和到期时间的摘要，默认 24 小时；V4.5 不做自动 L3 长期记忆。

### D10 主动消息预算

每用户滑动窗口预算：每小时最多 3 条、3 小时最多 10 条、24 小时最多 20 条；任何窗口均受总硬上限 30 和同机会仅一次约束。最终阈值通过测试调整，不改变架构。

### D11 数据源失败

天气或地图失败不阻塞聊天；保留上次仍未过期的数据，否则明确未知。外部请求使用超时、重试、熔断、缓存和配额告警。

### D12 模拟数据

仅开发/测试环境允许模拟数据；UI 和消息 evidence 必须显著标记。生产默认禁止模拟世界事实触发主动聊天。

### D13 AI 身份标识

群页固定显示“群成员为 AI 角色”，角色资料页和服务协议再次说明；生成文本在交互场景中采用统一显式提示，不把 AI 冒充真人作为体验目标。

### D14 安全优先级

自伤、自杀、暴力威胁、诈骗/重大财产损失等安全事件高于普通用户话题锁；进入专用安全响应，不进行角色化玩笑或多人起哄。

## 4. 推迟到 V5

- 周边 POI 搜索、热度/营业状态排序、接近和到达围栏。
- 实时道路、地铁、事故与拥堵。
- 新闻主动触发、展览、演出、节庆和景区通知。
- 图片上传和视觉理解。
- 角色关系数值成长和可视化。
- L3 自动长期记忆与内部梗沉淀。
- 更复杂的移动模式识别、连续步行判断。
- 系统通知和订阅消息策略。
- 多群、多角色、用户自建角色。

注意：未成年人、安全干预、AI 标识、投诉举报、数据权利、备案/评估不能因原路线未列出而推迟到 V5；它们是公开上线门槛。

## 5. 关键冲突与解决方案

| 冲突 | 处理 |
|---|---|
| 精准定位要求 POI，但 V5 才做 POI | V4.5 只用逆地理编码返回的地标；周边检索留 V5 |
| 世界面板列新闻/交通/活动，但原 V4.5 不接入 | 新闻按 ADR-019 接入可核验只读结果；交通和活动继续显示“未接入”或隐藏 |
| 用户消息绝对优先 vs 安全事件 | 安全事件是唯一高于普通话题锁的例外 |
| 所有消息必须有话题 vs 系统提示 | 系统提示使用 `system/safety` 话题或独立消息类型，不污染普通话题 |
| 3 小时至少 5 条 vs 无事沉默 | 去掉最低值，保留 0—20 和硬上限 |
| 群知道实时位置 vs 平台后台限制 | 改为“知道最近一次授权且有效的世界快照” |
| 模型人格稳定 vs 多模型/升级 | 角色卡版本化、评测集回归、模型版本固定与灰度升级 |

## 6. 平台限制

1. 地理位置属于隐私接口，需要在小程序后台配置隐私保护指引、说明用途并获得用户授权；相关接口权限可能需要单独申请和审核。
2. 小程序网络请求需要 HTTPS 与合法域名配置；第三方密钥应放后端，不能依赖客户端保密。
3. 小程序离开后不能继续执行普通前台逻辑；后台定位不能被当作通用常驻能力。
4. 主动通知受微信订阅消息机制和用户授权约束；V4.5 只承诺小程序内未读，不承诺系统推送。
5. 真实定位在开发者工具与真机、iOS 与 Android 之间行为可能不同，必须真机覆盖。
6. 小程序类目、AI/深度合成资质、隐私接口声明和实际代码必须一致，否则可能被驳回。

## 7. 数据源风险

| 风险 | 后果 | 控制 |
|---|---|---|
| 坐标系不一致 | POI/行政区错误 | 统一 GCJ-02，记录原始坐标类型 |
| GPS 漂移和室内误差 | 虚假到达事件 | accuracy 门槛、滞回、停留时间、距离阈值 |
| 逆地理编码不等于建筑内定位 | 错称“已进入” | 只说“附近/定位显示”，无围栏证据不说“已进入” |
| 天气站点代表性不足 | 局地天气不准 | 展示来源和更新时间，变化需阈值与持续性 |
| 预警重复或撤销 | 重复惊扰 | 使用 provider event id 去重，状态化更新 |
| 配额和限流 | 世界信息中断 | 缓存、请求合并、熔断、预算告警 |
| 商业授权/归因 | 下架或费用风险 | 上线前复核合同、归因和展示要求 |
| 数据过期仍进入模型 | 生成错误事实 | expiresAt 硬过滤，禁止模型自行补齐 |

## 8. AI 成本风险

原需求未定义 DAU、轮次、上下文长度和模型单价，当前无法给出可信金额。最大浪费源是“三个角色各调用一次 + 每次重复完整世界状态与长期记忆 + 后台无用户时持续生成”。

默认成本控制：

- 规则能决定沉默时不调用模型。
- 一次请求批量生成完整 1—3 条角色链。
- 世界状态只发送与当前机会相关的最小事实片段。
- L1 滑窗 + 摘要，不发送完整历史。
- 主动消息采用独立日预算和全局熔断。
- 缓存意图分类、地理编码和天气。
- 记录每轮输入/输出 token、延迟、模型、重试和归因用户。
- 预算耗尽时退化为单角色、短回复或沉默，不无上限重试。

## 9. 审核与合规风险

- 2026-07-15 起的拟人化互动服务规则高度适用本产品。
- 公开上线、重大功能变化、达到用户规模门槛等情形涉及安全评估；产品上线本身已被列为评估情形。
- 拟人化服务要求算法备案并接受年度核验。
- 调用已备案模型的应用/功能仍可能需要地方网信部门登记，并公示模型名称和备案号/上线编号。
- AI 生成文本属于生成合成内容，需要显式标识；下载、复制、导出时还要评估标识保留要求。
- 连续使用每超过 2 小时应提醒使用时长；发现依赖/沉迷倾向需动态提醒。
- 必须提供便捷退出、投诉举报、聊天复制/删除等能力。
- 对极端情绪、自伤自杀、重大财产损失等需有识别、安抚、求助和必要干预机制。
- 精准轨迹属于敏感个人信息；处理需要特定目的、充分必要、严格保护和单独同意等措施。
- 知名角色名称、头像、台词和相似宣传可能产生知识产权及不正当竞争风险。

这些事项需要正式法律/合规审查，本文只用于产品与工程规划。
