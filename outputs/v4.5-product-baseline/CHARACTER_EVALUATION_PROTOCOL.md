# AI 群角色活人感评测协议

> 协议编号：CLS-EVAL-1.1  
> 冻结日期：2026-07-27  
> 适用范围：V4.5 当前角色及后续新增角色  
> 关联标准：`CHARACTER_LIFELIKENESS_STANDARD.md`

---

## 1. 评测目标

本协议同时验证两件事：

1. 单个角色是否满足活人感准入标准。
2. CLS 标准的高分是否确实对应用户感知到的“像持续存在的群友”，而不是只对应文案流畅度。

评测不以某一句台词是否完全一致为目标，而关注跨场景、跨轮次和群体互动中的稳定行为模式。

## 2. 评测前版本锁定

每次评测必须记录并冻结：

- 角色 ID 与角色合同版本。
- 模型供应商、模型名称和版本。
- 系统提示词、导演提示词及模板版本。
- 温度、采样参数和最大输出长度。
- GroupState、角色状态和关系初始值。
- 记忆快照版本。
- 世界状态、证据和模拟数据标识。
- 代码提交或构建版本。
- 评测题集版本和随机种子。

任一关键项变化后，旧结果只能作为参考，不能直接证明新版本已通过。

## 3. 五级评测流程

### L0：角色合同审计

- 检查角色合同是否完整。
- 检查是否只靠形容词、口头禅或受保护角色名称建立差异。
- 检查与现有角色的功能位是否重叠。
- 检查硬规则、条件规则和概率偏好是否分离。

### L1：单轮场景测试

- 验证首条回应相关性、发言动机、表达自然度和事实边界。
- 覆盖普通问题、情绪、请求、纠正、无意义输入等场景。

### L2：连续性测试

- 通过多轮对话验证立场、情绪、关系、承诺和记忆的连续性。
- 验证角色会变化，但变化必须可由事件解释。

### L3：群体互动测试

- 验证角色会回应用户和前一位角色，而不是各说各的。
- 验证角色能让位、沉默、反对、补充和修复关系。
- 验证 Director 没有把角色差异压平成固定轮流发言。

### L4：用户盲测

- 隐藏角色身份进行辨识测试。
- 进行基础版本与完整角色系统的 A/B 偏好测试。
- 收集用户对“像长期存在的群友”的主观评分和原因。

L0—L4 应按顺序执行。前一级出现硬门槛失败时，停止准入流程并修复。

## 4. 场景覆盖

每个角色至少覆盖以下 15 类场景：

1. 普通问候。
2. 明确问题。
3. 请求帮助。
4. 开心或兴奋。
5. 低落或焦虑。
6. 新话题覆盖旧话题。
7. 用户纠正角色。
8. 用户表达行动计划。
9. 可靠的位置或天气变化。
10. 现实数据缺失、过期或冲突。
11. 另一角色先回应。
12. 群内轻微分歧。
13. 话题降温和结束。
14. 数小时后恢复共同经历。
15. 没有明确发言理由，应保持沉默。

最低样本量：每个角色不少于 30 个不同场景输入，每个输入生成 5 次，共不少于 150 个输出样本。安全和高风险事实场景单独计数，不得用普通聊天样本替代。

## 5. 评分维度与方法

每个样本按 1—5 分评分：

- 1 分：明显失败或与角色冲突。
- 2 分：存在较大问题，用户容易感到机械。
- 3 分：基本可用，但差异、连续性或自然度不足。
- 4 分：表现稳定且自然，只有轻微问题。
- 5 分：行为动机、关系和上下文高度一致，且没有表演痕迹。

维度权重采用 CLS v1.1：

| 维度 | 权重 |
|---|---:|
| 身份连续性 | 20 |
| 发言动机 | 15 |
| 上下文理解 | 15 |
| 关系连续性 | 15 |
| 时间与记忆连续性 | 15 |
| 变化与克制 | 10 |
| 表达自然度 | 10 |

总分计算：各维度平均分除以 5，再乘以对应权重后求和。

## 6. 客观质量指标

| 指标 | 准入目标 |
|---|---:|
| 用户明确问题的首条回复直接相关 | ≥ 90% |
| 后一位角色接住上一位角色 | ≥ 80% |
| 同一轮围绕当前主题 | ≥ 80% |
| 盲测角色辨识率 | ≥ 70% |
| 完整角色系统在 A/B 中被偏好 | ≥ 65% |
| 20 轮内无不可解释的人格矛盾 | ≥ 95% |
| 重要有效记忆的正确使用率 | ≥ 80% |
| 虚假记忆 | 0 |
| 无证据的现实事实断言 | 0 |
| 已入账角色故事关键事实矛盾 | 0 |
| 虚构用户共同经历 | 0 |
| 用户在 AI 播放期间有效打断 | 100% |
| 近重复表达占比 | ≤ 20% |
| 无必要发言占比 | ≤ 15% |
| 发言具备明确对象、动机和新增价值 | ≥ 90% |
| 合格议题产生可观察状态变化 | ≥ 85% |
| 用户必须连续催促才能推进 | ≤ 10% |
| 固定条数造成的人工截断 | 0 |
| 已无新增价值仍继续输出 | ≤ 5% |
| 暂停议题从正确开放分支恢复 | ≥ 85% |

客观指标不能替代 CLS 评分；CLS 高分也不能抵消硬门槛失败。

## 7. 角色辨识盲测

### 7.1 材料处理

- 隐藏昵称、头像、角色 ID 和明显身份标签。
- 去掉直接暴露原型或版权角色名称的句子。
- 保留必要上下文，但不要向评测者展示角色合同。
- 混合不同场景和不同角色样本，随机排序。

### 7.2 任务

评测者选择最可能的角色，并填写判断依据。当前三个角色使用三选一；未来角色增加后，采用随机四选一或成对比较，避免候选过多导致结果失真。

### 7.3 通过条件

- 总辨识率不低于 70%。
- 辨识依据应主要来自关注点、决策方式和关系行为，不能主要来自口头禅。
- 如果去除口头禅后辨识率大幅下降，应判定角色结构仍不充分。

## 8. A/B 活人感验证

### 8.1 对照条件

- A 版本：只使用简短人格形容词和基本安全规则。
- B 版本：使用完整角色合同、状态、关系、记忆、发言动机和克制规则。
- 两组使用相同模型、输入、世界状态、采样参数和展示界面。

### 8.2 评测问题

评测者回答：

1. 哪一版更像一个持续存在、有自己关注点的群友？
2. 哪一版更愿意继续聊？
3. 哪一版更能记住和延续关系？
4. 哪一版更少像按标签表演？

并对“像持续存在的群友”进行 1—7 分评分。

### 8.3 通过条件

- B 版本总体偏好率不低于 65%。
- B 版本在“像持续存在的群友”上平均至少领先 A 版本 1 分。
- 若 B 只在文采上领先、在连续性和关系感上没有领先，不视为验证成功。

## 9. 连续性专项测试

每个角色至少运行 5 组独立的 20 轮会话，并包含：

- 用户提出计划，稍后修改计划。
- 角色表达一个立场，随后遇到反例。
- 用户与角色发生轻微分歧并修复。
- 话题中断后再返回。
- 数小时后的状态变化。
- 短期记忆过期。
- 用户纠正错误信息。
- 另一角色先回答并提出不同意见。
- 现实证据缺失或来源冲突。
- 当前没有继续发言价值。
- 角色分享相关固定故事或已入账虚拟生活片段。
- 用户在角色继续交流时插话并切换焦点。
- 用户停止发言后，角色依据未完成分歧把事情聊到自然暂停。
- 一个角色被新证据说服、部分让步或明确保留意见。
- 讨论形成事实、观点、分歧、开放问题或下一步之一的可观察变化。
- 已无新增价值时不因固定条数或活跃目标继续发言。

重点记录人格矛盾、虚假回忆、情绪瞬移、无理由关系跳变、重复套路和不肯沉默。

## 10. 评测者与一致性

- 每个样本至少由 3 名评测者独立评分。
- 初次内部冻结建议至少 5 名盲测评测者。
- 进入 V4.5a 受邀体验后，建议累计不少于 20 名真实用户。
- 评测者间对“通过/不通过”的一致率低于 70% 时，应先修订评分锚点，而不是直接取平均掩盖分歧。
- 产品负责人不得单独评定自己编写的角色为通过。

## 11. 如何验证标准本身是否合理

CLS 不是永久正确的主观清单，需要用数据校准：

1. 使用历史上的好、坏和边界样本进行回放，确认标准能区分明显差异。
2. 比较 CLS 总分与用户“愿意继续打开”和“像群友”的评分是否同向变化。
3. 分析各维度与用户偏好的关联；长期无区分力的维度应修订定义或权重。
4. 保留硬门槛独立判断，禁止因文案自然而放过虚假事实、虚假记忆或身份欺骗。
5. 每次只调整一个主要变量，避免模型、提示词、状态机和 UI 同时变化导致无法归因。
6. 标准或权重变化必须建立新版本并重新跑代表性回归集。

## 12. 准入条件

一个角色只有同时满足以下条件才能标记为“已准入”：

- 角色合同完整。
- 所有硬门槛通过。
- CLS 总分不低于 75。
- 身份连续性不低于 16/20。
- 上下文理解不低于 12/15。
- 其余每个维度达到该维度满分的 60%。
- 角色辨识率不低于 70%。
- A/B 活人感偏好率不低于 65%。
- 连续性专项测试通过。
- 评测报告、失败样本和版本信息已归档。

任何一项未满足，只能进入内部试验，不得因为个别演示对话表现好而豁免。

## 13. 回归触发条件

以下变化后必须重新评测受影响部分：

- 更换模型或模型大版本。
- 修改系统提示词、角色合同或 Director 规则。
- 调整记忆提取、关系状态或情绪状态逻辑。
- 增加新角色，改变现有角色的群体功能位。
- 修改真实性证据规则或外部数据源。
- 用户反馈出现人格漂移、机械复读、假记忆或抢话问题。

涉及核心人格、硬门槛或模型大版本时，必须执行完整 L0—L4 回归。

## 14. 评测报告模板

每次评测至少归档以下内容：

| 项目 | 内容 |
|---|---|
| 角色与合同版本 | 待填写 |
| 模型、提示词与构建版本 | 待填写 |
| 题集版本与样本量 | 待填写 |
| CLS 各维度得分 | 待填写 |
| 硬门槛结果 | 待填写 |
| 客观指标结果 | 待填写 |
| 盲测辨识率 | 待填写 |
| A/B 偏好率 | 待填写 |
| 连续性测试结果 | 待填写 |
| 主要失败模式 | 待填写 |
| 失败样本地址 | 待填写 |
| 修复建议 | 待填写 |
| 评测者与日期 | 待填写 |
| 最终结论 | 通过 / 有条件通过 / 不通过 |

“有条件通过”只允许进入内部测试，不等同于产品准入。
