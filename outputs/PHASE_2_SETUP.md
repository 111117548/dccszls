# Wchat V4.5 阶段 2：真实定位与天气接入

更新日期：2026-07-14  
状态：代码与自动化测试完成；等待微信云函数部署和真机联调

## 已完成

- `project.config.json` 已配置实际小程序 AppID。
- `app.json` 已声明 `scope.userLocation` 和 `requiredPrivateInfos: getLocation`。
- 小程序启动时初始化微信云开发，不在代码中固定云环境 ID。
- 世界状态页可由用户主动触发前台高精度定位。
- 定位结果记录 GCJ-02、精度和采集时间。
- 新增 `weatherSnapshot` 云函数。
- 云函数从环境变量读取和风天气凭据，不接受客户端传入 Key 或 Host。
- API Host 使用严格域名白名单，避免任意外部主机请求。
- API Key 通过 `X-QW-Api-Key` 请求头发送，不拼进 URL、不写日志。
- 天气实况包含温度、体感、湿度、风、过去一小时降水、观测时间和数据来源。
- 天气预警接口失败不会拖垮实况天气；有预警时保留官方预警 ID 和标题。
- 坐标按和风接口能力降到小数点后两位后再提供给天气服务。
- 相同坐标网格缓存 10 分钟，减少费用和重复请求。
- 真实结果被包装为 `EvidenceEnvelope`，包含来源、观测时间、获取时间、有效期和置信度。
- 群聊页返回后会读取最新世界状态；本地模拟回复与真实世界事实分别标识。

## 没有保存的敏感信息

- 用户提供的天气 API Key 没有写入任何项目文件。
- 用户提供的 API Host 也没有写入源码，与 Key 一起由云函数环境变量管理。
- 旧版 DeepSeek Key 没有迁入当前项目。
- 自动扫描结果：当前 `miniprogram/` 和 `cloudfunctions/` 中潜在已提交密钥为 0。

## 部署步骤

### 1. 配置小程序隐私指引

在微信公众平台为“小程序获取你的位置信息”填写实际用途，并确认体验版可以调用 `getLocation`。

### 2. 设置云函数环境变量

在微信云开发控制台的 `weatherSnapshot` 云函数配置中添加：

```text
QWEATHER_API_KEY=<新生成或确认可用的天气凭据>
QWEATHER_API_HOST=<专属 API Host>
```

不要把真实值写入 `.env.example`、`app.ts`、页面设置、本地存储或截图。

### 3. 上传云函数

在微信开发者工具中找到 `cloudfunctions/weatherSnapshot`，执行“上传并部署：云端安装依赖”。此函数没有第三方 npm 依赖。

### 4. 真机验证

1. 打开世界状态页。
2. 点击“同步真实世界状态”。
3. 同意定位授权。
4. 确认页面从黄色“模拟数据”切换为绿色“真实数据已同步”。
5. 检查位置精度、天气来源、观测时间、有效期和归因信息。
6. 回到群聊页，询问“现在天气怎么样”，确认回复引用真实状态并仍标记为模拟回复。

### 5. 失败排查

- `weather_service_not_configured`：云函数环境变量未配置或 Host 不符合专属域名格式。
- `cloud_not_available`：云开发未初始化或当前体验版没有绑定环境。
- `permission_denied`：定位权限未开启；使用页面上的“打开定位权限设置”。
- `weather_unavailable`：检查和风项目权限、配额、API Host 和凭据状态。
- 云函数找不到：确认函数名严格为 `weatherSnapshot` 并已上传到当前环境。

## 当前仍缺少

- 腾讯位置服务或其他合规地图服务凭据，因此街道、详细地址、建筑物和附近 POI 尚未接入。
- 当前和风 GeoAPI 只用于城市/区县级展示，不能替代详细逆地理编码。
- 尚未选择并接入已备案的大模型。
- 当前环境没有微信开发者工具，无法代替用户完成体验版编译和真机授权测试。
