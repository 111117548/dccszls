# 阶段 7：群会话、事件与记忆持久化

## 已实现

- 数据按微信云函数上下文中的 `OPENID + groupId` 隔离，客户端不能传入用户身份。
- 四个已注册群分别保存群状态、模式状态、最近消息、未读数和已读时间。
- EventLedger 保存可信现实机会的待处理、已消费、过期状态；同一机会幂等去重。
- 用户记忆只保存明确偏好、不喜欢、近期计划和短期情绪；普通闲聊不自动进入长期记忆。
- 用户可在记忆页清空当前群记忆；云端删除失败时，本地墓碑会阻止旧记忆在下次同步时复活。
- 云函数不可用时保留本地记录，聊天本身不被持久化故障阻断。

## 需要部署

在微信开发者工具中右键 `cloudfunctions/groupPersistence`，选择“上传并部署：云端安装依赖”。该函数不需要业务环境变量。

## 云数据库集合

在当前云开发环境创建：

```text
wchat_group_sessions
wchat_group_messages
wchat_group_events
wchat_group_memories
wchat_group_assets
```

五个集合都禁止小程序端直接读写：

```json
{
  "read": false,
  "write": false
}
```

所有访问统一经过 `groupPersistence`。

## 组合索引

| 字段 | 排序 |
|---|---|
| `ownerOpenId` | 升序 |
| `groupId` | 升序 |
| `createdAt` | 降序 |

| 字段 | 排序 |
|---|---|

| 字段 | 排序 |
|---|---|

## 验证

1. 分别进入四个群，每个群发送一条不同消息。
2. 退出并重新进入，确认每个群只恢复自己的消息与模式状态。
3. 在陪伴群说“我喜欢散步”，打开“记忆”，确认出现长期偏好。
4. 说“我准备明天去看展”，确认出现有期限的短期计划。
5. 清除当前群记忆，退出并重进，确认不会恢复。
6. 制造一次可信天气或跨城变化，确认事件最多触发一次。
7. 返回群列表，确认最新消息、未读数和时间来自真实记录。

若顶部持续显示“本地记录”，依次检查云函数部署、五个集合、四个组合索引、云环境和 AppID。

## 安全边界

- 云函数只接受四个注册群和三名注册 AI 角色。
- 单次消息写入最多 10 条，单条最多 1000 字；未知字段会被丢弃。
- 事件、模式状态和记忆都经过独立白名单净化。
- 图片资产按用户和群绑定；只有已登记为 active 的资产才能进入消息或视觉识别。
- 原始精确坐标不进入聊天消息、事件证据或记忆。
- 云端数据保留期和账号级删除仍是公开版上线前的发布门槛。
