# 飞书整改任务问题说明与图片：上线验收

## 部署

1. 在微信开发者工具中，对 `cloudfunctions/feishu-rectification` 执行“上传并部署：云端安装依赖”。必须包含新增的 `evidence.js`。
2. 保留现有云函数环境变量和表格权限。客户端和云函数版本标记均为 `feishu-user-visible-projects-v15-evidence-relink`。
3. 重新编译并预览小程序。进入质量检查台账同步任务，再打开一条整改任务，点击“刷新飞书”。
4. 正式版需重新上传、审核和发布小程序；仅部署云函数不会更新已发布页面。

## 数据来源

- 问题说明：默认读取“存在质量问题”，兼容“问题描述”等已有字段别名。
- 问题图片：读取“问题”附件列。
- 整改后图片：读取“闭环”附件列，与小程序提交的整改证据分组展示，不当作问题图片。
- 现有 `FEISHU_FIELD_DESCRIPTION`、`FEISHU_FIELD_SOURCE_IMAGES`、`FEISHU_FIELD_CLOSURE_IMAGES` 配置仍优先。

飞书附件的 `tmp_url` 可能是需要认证的 API，不是图片本身。本次按任务调用 [飞书获取素材临时下载链接接口](https://open.feishu.cn/document/server-docs/docs/drive-v1/media/batch_get_tmp_download_url)，保留返回的附件权限参数，在云端换取可展示链接。不会把飞书访问令牌放到页面，也不会为刷新图片执行全表同步或回写整改状态。

## 真机验收

- 找一条说明较长、带换行且有多张“问题”图片的任务：说明完整显示，缩略图可点击预览全部问题图片。
- 同时含“问题”和“闭环”附件的任务：两类图片不混在一起。
- 在飞书修改说明、增删附件，点击刷新：显示最新内容，删除全部问题图片后不再显示旧照片。
- 项目只读人员仍能查看问题内容，但原有分享、提交和验收权限保持不变。
- 把任务分享给施工人员：无需飞书登录即可通过有效分享链接读取该任务；失效链接不可读取。
- 图片接口无权限、超时或真机网络加载失败：显示错误和重试入口，不能误报“未上传图片”；原整改状态保持不变。
- 如开发工具正常、真机图片失败，检查实际临时图片地址对应的域名及预览所需域名配置；不要用关闭域名校验作为上线解决方案。
